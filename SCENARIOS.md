# Покрытие тестами — отчёт по сценариям

Единый отчёт «какие сценарии покрыты» (критерий «Тестирование» жюри).
Автотесты запускаются из пайплайна GitLab CI на каждый коммит и MR.

## Как запустить

| Команда | Что делает |
|---|---|
| `cd backend && uv run pytest --cov=app` | все тесты бекенда + отчёт покрытия |
| `cd frontend && npm test` | юнит-тесты фронтенда |
| `cd frontend && PETCARE_TEST_PYTHON=../backend/.venv/bin/python npm run test:integration` | интеграционные тесты фронтенда против реального FastAPI |

**Итого: 157 автотестов.** Все тесты бекенда и интеграционные тесты фронтенда —
сквозные: реальное приложение FastAPI с настоящей БД (изолированная SQLite),
HTTP-запросы через весь стек (роутер → сервисы → БД). Изоляция данных: каждый
тест получает чистую базу, тесты разных пользователей/питомцев не пересекаются.

## CI (`.gitlab-ci.yml`)

- `test:backend` — pytest + junit-отчёт + cobertura-покрытие (процент виден в MR и пайплайне)
- `test:frontend` — юнит-тесты (node:20)
- `test:frontend:integration` — интеграционные (node:20 + uv-окружение бекенда)
- `lint:backend` — ruff (E/W/F/I/B/UP) по бекенду
- `lint:frontend` — eslint по фронтенду
- `test:migrations:postgres` — весь Alembic-граф против настоящего PostgreSQL
  (upgrade → downgrade → upgrade), ловит диалект-специфичные ошибки миграций

Все джобы идут в стадии `test` до `build`/`deploy`: красный тест или линтер
блокирует сборку и выкатку. На деплое миграции применяются в одноразовом
контейнере до перезапуска `api`/`site`.
